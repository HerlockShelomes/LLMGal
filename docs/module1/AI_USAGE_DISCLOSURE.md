# 模块一 AI 使用披露与关键对话摘要

记录日期：2026-09-10  
工具：OpenAI Codex（当前协作会话）  
关联分支：`codex/module1-testing`

## 重要说明

课程《实践作业要求 v2026》第 3.1.1(g) 明确要求模块一不得使用 AI 生成测试用例或开展自动化测试。本分支中的自动化测试、代码整改建议和报告草稿存在 AI 参与，因此不能被表述为“完全人工完成”。提交课程作业前，应向任课教师如实说明并确认这些材料是否可以作为学习参考、草稿或补充证据使用。

本记录用于满足课程关于“关键 AI 对话记录应使用 Git 版本管理”的要求，也用于避免把 AI 生成内容伪装成人工作业。

## 关键用户请求与 AI 处理摘要

### 1. 阅读作业要求并分析被测项目

用户请求：阅读课程 PDF，拉取并分析 `HerlockShelomes/LLMGal`，完善 README 并提交仓库，同时解释直接修改与 PR 的区别。

AI 处理：读取 PDF 和仓库结构，改写 README，创建分支并提交；随后通过 PR #1 合并到 `main`。同时指出仓库中存在不应公开的硬编码凭据，真实凭据必须轮换。

### 2. 解释模块一前四项所需知识及测试用例格式

用户请求：以零基础视角解释完成模块一前四项需要掌握的知识，并给出一条手工测试用例示例。

AI 处理：解释等价类、边界值、场景法、pytest、Mock、缺陷生命周期和测试报告结构；根据课程模板说明正式用例所需字段。

### 3. 阅读课程附件模板

用户请求：阅读测试用例清单、缺陷报告和模块一测试报告模板。

AI 处理：核对了 Excel 和两个 Word 模板的栏目、章节和统计要求，确认测试报告模板要求至少 30 条用例、至少 24 条自动化用例。

### 4. 完成模块一自动化脚本、缺陷清单和测试报告

用户请求：基于 PDF 与 34 条 Markdown 用例，完成自动化测试、缺陷报告和测试报告，并将代码、测试数据、配置和关键 AI 对话记录纳入 Git 与 GitHub。

AI 处理：

- 将外部文本、语音和图片服务全部替换为测试中的 Mock/Stub，避免联网和费用；
- 按用户确认，Mock 只返回预先写定的固定文本、固定二进制数据或固定异常；模块一不调用任何真实大模型；
- 建立 Python 3.11 独立测试环境和一键测试脚本；
- 先运行修复前回归测试并保存失败证据，再整改缺陷并重复回归；
- 依据真实测试结果填写老师提供的 Word 缺陷报告和测试报告模板，并完成逐页版式检查；
- 建议现场以本地一键测试为主、GitHub Actions 为备份，不部署需要真实密钥和外部 API 的完整应用。

## 人工复核建议

提交前由学生本人逐项完成以下复核，并在课堂上能够独立解释：

1. 阅读每条测试的前置条件、Mock、操作与断言。
2. 手工执行一遍一键脚本并理解失败/通过输出。
3. 对照 Git 提交复述至少三个缺陷的“现象—原因—修复—回归”。
4. 检查报告中的每个数字均能由测试日志或 Git 记录验证。
5. 先向教师确认模块一使用 AI 形成的材料是否允许提交。
